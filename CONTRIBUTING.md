# Contributing

## Scope and process

- Read the active milestone in `project-plan/` before editing.
- Keep scope narrowly aligned to that milestone.
- Use small, reviewable, descriptive commits.
- Add documentation updates for repository or behavior changes.
- Add acceptance evidence for changes that affect behavior.
- Do not mark incomplete work as complete.

## Commit message examples

- `docs: lock release 1 product specification`
- `chore: initialize repository structure`
- `feat(queue): add atomic call-next operation`
- `fix(billing): prevent duplicate usage reporting`
- `test(auth): cover revoked refresh token`

## Security and compliance

- Do not commit secrets, credentials, or customer data.

## Completion reporting

- Record blockers and evidence paths clearly.
- Never claim a milestone complete without evidence and milestone report files.
