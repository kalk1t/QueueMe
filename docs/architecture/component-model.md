# Backend Component Model

## Boundary model

Backend remains modular-monolith-first with service boundaries defined by domain components.

| Component | Owner | Public interface | Data ownership | Transaction boundaries | Events emitted | Events consumed | Authorization | Idempotency | Audit requirements |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Authentication and sessions | Platform identity team | `POST /auth/*`, session issuance, logout, token refresh | Session table, account identity | Login, password reset, session rotation per user request | `auth.session.revoked`, `auth.password.changed` | `identity.signOut` | Multi-factor optional, role checks on all protected resources | Non-critical for login retries, one-time token mint dedupe | All account/auth changes must be auditable |
| Authorization and role enforcement | Security owner | RBAC policy engine, endpoint guard filters | Role grants table with org/location scoping | Every protected mutation request | `authz.denied` for denied operations | Identity and staff assignment | Mandatory role + location guard | `if_match_revision` for policy rechecks not replayed by stale cache | Denied attempts logged with actor + requested scope |
| Organizations | Product/platform | Organization CRUD, lifecycle management | `organizations`, `organization_memberships` | Owner/organization creation, update, deactivation | `org.created`, `org.deactivated` | AuthN context and staff assignment | Owner and platform-admin approvals as required | Idempotent on create/update by request token | Org-level ownership changes always audited |
| Locations | Operations owner | Location CRUD and settings | `locations`, `location_settings` | Create/update with organization guard | `location.created`, `location.updated`, `location.subscope_changed` | Onboarding, entitlements, messaging-number | Location-scoped access validation | Idempotent updates using revision checks | Sensitive changes in settings are recorded |
| Staff and assignments | Operations owner | Add/remove staff, role assignment | `staff_assignments` | Role assignment and role changes | `staff.assigned`, `staff.revoked` | Authorization service, org/location | Requires role owner privileges | Idempotency keys for repeated assignment |
| Administrator approval | Admin operations | Approve/reject trial and onboarding requests | `admin_requests`, `onboarding_journeys` | Request review transitions | `onboarding.approved`, `onboarding.cancelled` | Billing/trial subsystem | Platform-admin scope only | Request idempotency by request token | Every manual action audited |
| Entitlements | Billing owner | Location entitlement queries and enforcement | `location_entitlements`, `subscription_state` | Trial and subscription state machine transitions | `entitlement.activated`, `entitlement.conversion_blocked` | Billing and queue components | Auth + entitlement checks for all operations | Idempotent onboarding state transitions | All entitlement transitions are auditable |
| Trials and subscriptions | Billing owner | Trial path, cancellation paths, conversion logic | Trial/subscription records | Trial start/end, cancellation and paid transition | `trial.requested`, `trial.state_changed` | admin approval, payments | Payment and approval checks | Idempotent trial requests and cancellation actions | Cancellation and conversion decisions audited |
| Billing and reconciliation | Billing owner | Invoice generation, usage charges, invoice state | `invoices`, `subscription_charges`, `payment_methods` | Charge posting and dispute/failure transitions | `billing.invoice.generated`, `billing.payment.failed` | Job processor, provider adapters | Billing scope + role checks | Idempotent invoice and payment event handling | Billing actions with hashable audit context |
| SMS usage ledger | Messaging owner | Segment counters, overage state, caps | `sms_ledger`, `usage_events` | Consume/release per provider event or operator send | `sms.allowed`, `sms.capped`, `sms.overage_rejected` | Queue messaging, provider callbacks | Entitlement and staff checks | Idempotent consumption by provider event ID + request key | Ledger updates auditable |
| Messaging-number lifecycle | Messaging owner | Provision/deprovision and assignment states | `message_numbers`, `number_assignments` | Number request and reassignment transaction | `number.assigned`, `number.decommissioned` | Billing + location entitlements | Strict location ownership | Idempotent number assignment keys | Number lifecycle transitions logged |
| Consent | Privacy owner | Consent capture and lookup | `consent_records` | Capture at check-in time with evidence fields | `consent.captured`, `consent.revoked` | Queue messaging | Consent scope checked per location and queue entry | Request idempotency by queue entry + method + version | Evidence capture and revocation audit |
| Messaging templates | Messaging owner | Template edit/read/preview | `sms_templates`, `template_versions` | Template draft/save/publish operations | `template.published` | Queue events, consent checks | Owner/admin scope | Idempotent saves by actor + template version | Template moderation actions audited |
| Queue configuration | Queue owner | Queue and service configuration | `queues`, `services`, `queue_rules` | Queue add/edit and cap changes | `queue.configured` | Queue-entry component | Location role checks | Idempotent config updates by revision | Config change audit with old/new values |
| Queue-entry state machine | Queue owner | Entry transitions, transitions constraints | `queue_entries`, `queue_entry_transitions` | Create / call / serve / complete / cancel / remove / no-show states | `queue_entry.state_changed` | Queue concurrency and contracts | Role + location check on each state change | Idempotent transition IDs with stale revision guard | State transitions recorded for conflict trail |
| Queue ordering | Queue owner | ordering service, position changes | `queue_positions`, `entry_reorders` | Default FIFO and manual reorder with reason constraints | `queue.ordered`, `queue.reordered` | Queue-entry and audit | Operator role and location checks | Idempotent reorder operations by position + reason token | Reason text required, always logged |
| Wait estimation | Product analytics | Estimation inputs and computed field | Derived from order history and recent service durations | Calculated read, optional recalculation job | `wait.estimated` (derived) | Queue ordering + status surface | Same as location scope of queue | Deterministic estimation cached by revision | Audit when formula version changes |
| Customer check-in | Customer/public surface owner | Check-in and customer metadata intake | `checkin_attempts`, `queue_entries` | Validation + queue assignment transaction | `customer.checked_in` | Queue-entry, consent, privacy | Required phone/name checks + location policy | Idempotent check-in by phone+queue+request fingerprint | Check-in evidence stored with immutable metadata |
| Customer status | Customer surface owner | Private status endpoint and tokenized access | `queue_entries`, `customer_status_sessions` | Read-only status refresh, optional cached state | `status.session.started`, `status.session.ended` | Websocket and API | Session/location constraints | Request dedupe for status polling tokens | Access to full phone number logged |
| Audit | Platform security | Write-once audit stream/query | `audit_events`, `audit_actors` | Append-only writes inside service transaction | Broad event bus for all critical actions | All components publish to audit sink | Scope-limited read/write audit views | Idempotent audit event dedupe by event key | Immutable retention controls, hash chaining if available |
| Retention/deletion | Data governance | retention schedule and deletion tasks | `retention_rules`, `deleted_identity_payloads` | Deletion transaction and archival transition | `retention.cycle.run`, `retention.record_anonymized` | Data model, audit and privacy controls | Governance role for manual delete actions | Job-level idempotent deletion actions | Deletion operations logged with reason and actor |
| Provider integrations | Platform integrations owner | Stripe/Twilio adapter interface | Provider mapping and event tracking tables | Send/reconcile side-effects and callback processing | `provider.event.ingested`, `provider.event.dequeued` | Billing and SMS components | Adapter calls by backend services only | idempotency keys and provider event dedupe | Provider error and override actions audited |
| Realtime synchronization | Platform platform | Websocket sessions and event fan-out | session state and connection cache | Event emission in transaction boundaries | `realtime.connected`, `realtime.dropped`, `realtime.delivered` | API mutation stream | Must be validated against actor and tenant scopes | Replayed/duplicate tolerant | connection/auth failures audited |
| Background jobs | Platform ops | Job orchestration and schedulers | `jobs`, `job_attempts`, outbox queues | Job creation + retry + dead-letter transitions | `job.started`, `job.completed`, `job.failed`, `job.dead_lettered` | webhook, webhooks, billing, queue cleanup | Worker roles and service tokens | Job keys per command correlation and idempotent steps | Job mutation outcomes auditable |
| Operational diagnostics | Operations team | Feature flags, health checks, incident evidence | `incidents`, `diagnostics` | Incident and retry control transactions | `ops.alert`, `ops.recovery.action` | Monitoring and observability | Read-only for non-admin roles | Idempotent alert suppression by signature | Operator manual actions audited |
